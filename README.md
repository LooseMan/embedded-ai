# embedded-ai

これは、エージェントに与える skill の効果を比較するための最小実験環境です。

## 定義

- `agents/modern-developer.md`: モダン開発者。`skills/modern-utf8/SKILL.md` を使用し、UTF-8 でファイルを扱う。
- `agents/legacy-developer.md`: レガシー開発者。`skills/legacy-euc-jp/SKILL.md` を使用し、EUC-JP を維持してファイルを扱う。
- `skills/preserve-encoding/SKILL.md`: 両エージェント共通。修正前後で文字コード、BOM、改行形式を変えない。
- `skills/encoding-converter/SKILL.md`: 両エージェント共通。指定した入力・出力文字コードへ、strict モードで安全に変換する。

両エージェントのタスク解釈と変更範囲は同じにし、文字コード方針を主な実験変数にします。

## エージェントとSkillの使い分け

- エージェント定義（`agents/`）には、プロジェクトや実験に固有の役割、前提条件、成果物の形式、比較条件を置きます。このリポジトリでは、レガシー開発者に対する日本語を含むC関数ヘッダの要求が該当します。
- Skill（`skills/`）には、複数のプロジェクトやエージェントで再利用できる手順・能力を置きます。文字コードの維持、変換、検証のように、特定プロジェクトの成果物形式に依存しないルールが該当します。
- プロジェクト固有の要求をSkillに入れると、別プロジェクトでSkillを再利用した際にも意図せず適用されるため、まずエージェント側への配置を検討します。複数プロジェクトで同じ要求が必要になった場合に限り、汎用化できる部分をSkillへ切り出します。
- エージェントからSkillを参照する構成にすると、エージェント側で実験条件を定義し、Skill側で共通手順を共有できます。今回もこの方針に合わせ、関数ヘッダの要求を `agents/legacy-developer.md` に置き、`skills/legacy-euc-jp/SKILL.md` からは削除しました。

## 測定方法

同一のプロンプトと同一の入力ファイルを、2 エージェントへ別々に与えて比較します。最低限、次を記録してください。

- タスク成功: 要求された機能・内容を満たしたか
- 文字コード安全性: 指定文字コードで読み書きでき、文字化けや `?` の混入がないか
- 変更の健全性: 不要な全体変換や改行変更がないか
- 検証の再現性: エージェントが完了時に実施した検証と、その結果
- 所要時間・ツール呼び出し数・追加修正回数

実験では、プロンプト、入力 fixture、評価基準、実行環境を固定し、エージェントの出力と Git diff を保存すると比較しやすくなります。

読み込み仕様と、手動指定・Skill 登録・Workspace Agent 登録の手順は [docs/agent-skill-loading.md](docs/agent-skill-loading.md) を参照してください。
